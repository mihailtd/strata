# Experiment Re-Audit — September 2026

## Why this exists

Two things happened close together: (1) the repo got reorganized into `experiments/`/`benchmarks/`/`evals/` (see `METHODOLOGY.md`), making it possible for the first time to see, per experiment, whether it actually graduated into a live `apps/runtime*` module; (2) we found and fixed a real integrity violation — `apps/harness/coordinator/subagent.py` and two now-deleted scripts were silently fabricating "agent-generated" code while reporting unconditional success (see `agent_sandboxes/README.md`'s "Removed" section).

Finding #2 raised an obvious question: if that got past review, what else has? This is a systematic re-audit of every cluster in `experiments/` (29 clusters, 3 parallel research passes) plus a cross-reference of every already-shipped `apps/runtime` module against which runtimes/model sizes actually exercise it. It answers, per cluster: worth revisiting or not (why), integrated in runtime A but untested in runtime B, worth a full harness-driven end-to-end eval, worth combining with another cluster now that something's been settled.

**Read the next section first.** It's more urgent than the categorization exercise that motivated this document.

## Category 5 — Worth combining, now that something's settled

- ~~`state_replay`'s branching/tree unlock + `weibull_hazard_gating`'s early-exit gate.~~ **DONE 2026-09-14, and it's closed negative.** This was picked up in full: the fork primitive and the gate were combined into a real, working tree-search policy (`experiments/runtime/speculative/state_replay/benchmark_gated_lookahead_policy.py`), calibrated against the real measured confidence distribution, and swept across thresholds. Don't re-attempt this exact combination without a genuinely different design (deeper search, a different selection criterion, or a different trigger signal) — see §79 for the three undiagnosed candidate reasons the first real attempt didn't work.
- **`poet_temporal_compression`'s state ring buffer (integrated) + `state_replay`'s branching capability.** Both already touch `apps/runtime/state_ring_buffer.py`; the compression work and the not-yet-built branching/tree consumer are two ends of the same infrastructure that haven't been connected.
- **`riemannian_metric`'s open activation-covariance thread + `copula_routing`/`gee_trajectory`.** All three are statistical-routing signals that have never been validated against a real model's actual activations (the first is explicitly flagged as such; the other two have never touched a real model at all). Rather than three separate synthetic-or-half-real validation passes, one shared real-activation statistical-routing evaluation would answer all three at once and would be the first real-data test any of them has had.
- **`apps/runtime/jump_streamer.py` (shipped, simple, real) vs. `benchmarks/superseded/frontier_fabricated/benchmark_jump_tokens.py` (fabricated, complex, never shipped).** Not a combination so much as a calibration exercise: compare the real macro-injection implementation's actual measured impact against what the fabricated benchmark predicted for the more elaborate design, to get an honest sense of how far off the other three frontier inventions' fabricated numbers likely are, by extension.
