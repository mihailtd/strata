# Superseded scripts

Kept for provenance only. **Do not cite their results and do not use them for new work.** Each file's docstring records why it was retired.

One unified graveyard regardless of which tree a retiree came from — `experiments/`, `benchmarks/`, or `evals/` (see the repo's [`docs/METHODOLOGY.md`](../../docs/METHODOLOGY.md) for what those mean). A retired idea doesn't need its own per-tree superseded/ folder; it needs a retirement rationale next to every other one, so "has this been tried and rejected before" is one grep away.

| script | why |
| :--- | :--- |
| [`sla_cluster_scheduler/`](sla_cluster_scheduler/) | **SLA-bounded cluster scheduler + its two benchmarks.** Not retired for being wrong — it worked, and beat both baselines on deadline misses (SLA violations 98% → 79.5% at ρ=1.5, 62.5% → 47% at ρ=0.95). Retired because **the engine has no concurrency to schedule**: single-tenant, one agent walking a deterministic tool DAG, one node active at a time. With one caller there is nothing to reorder, so it is inert by construction, and the minority-domain starvation it guards against cannot arise. The live A/B agreed in advance — swap overhead is 0.86% of wall clock, mean latency −62 ms with 95% CI [−1481, +1417] (not significant), and batch-order commitment cost +3.6 s of P95. **Revive only if the engine becomes multi-tenant.** The measured cost model it sat on stays live in `router/vram_state_router.py`. See `docs/DECISIONS.md` §6. |
| [`clime_head_crosstalk/`](clime_head_crosstalk/) | **CLIME sparse precision inversion for attention-head cross-talk (Ch.4 §4.4.3), and its benchmark.** Not retired for being wrong — its entrywise guarantee `||SΘ−I||∞ ≤ λ` held exactly on every feasible column at every λ. Retired because (1) **graphical lasso beats it at n/d ≤ 1** — the B=1 decode regime it was proposed for — while being ~35× faster (1.3 ms vs 48 ms at d=32), λ chosen honestly by eBIC on both arms; and (2) **the real head graph is not reproducible at decode window sizes**: two disjoint 32-token windows of real `Qwen3.5-4B` activations each find ~80 head edges and share **zero** (Jaccard 0.000; ~512 tokens needed for even half-agreement). Finding (2) is a property of the ACTIVATIONS, not the estimator, so it closes the whole application — **do not route or prune attention heads from a per-token head graph with any method.** `graphical_lasso_admm` (the winner) stays live in `src/runtime/clime_precision.py`. **Read its README before proposing any per-token head graph.** See `docs/DECISIONS.md` §66. |
| `cuda_graph_ftq_prototype.py` | **Orphaned duplicate.** Sat at the repo ROOT as `cuda_graph.py`, colliding by filename with the live `src/runtime/cuda_graph.py`. It defines `CudaGraphDecoder` (108 lines) while the live engine is `FoldedCudaGraphDecoder` (346 lines); nothing imported it. It is an **ftq-era prototype** — `ftq_0.8b_experiments.md` (moved from root `EXPERIMENTS.md`) T-12 documents its home as `src/ftq/tricks/cuda_graph.py`, a path that does not exist in this repo. ⚠️ T-12's numbers (83.94 tok/s FP16, 84.39 tok/s GPTQ-3b, 1.58x) are from that other project on a different model and **must not be quoted as results of this repo**, whose bf16 Qwen3.5-4B baseline is ~32 tok/s. |
| `ftq_0.8b_experiments.md` | **Historical FTQ (Fast Token Quantization) tracker on Qwen3.5-0.8B (FP16).** Moved from root `EXPERIMENTS.md`. Documents past exploratory experiments (T-01 to T-17) on a different model/toolchain. |
| `AUDIT_HISTORY_2026-08-11.md` | **Historical 2026-08-11 audit narrative & bug analysis.** Moved from the original monolithic `TODO.md`. Preserves the detailed mathematical autopsy of the 18x `kaiming_uniform_` fan_in initialization bug in transposed linear layers, on-disk size inflation fixes, and the discovery of cross-task SVD subspace orthogonality. |
| [`ftq_w4a16_hip_kernel/`](ftq_w4a16_hip_kernel/) | **Hand-written HIP C++ W4A16 GEMV kernel** (register-level 4-bit dequant, no shared memory) plus its Python quantize/pack reference, from the early FTQ line of work on Qwen3.5-0.8B. Not retired for being wrong — measured **2.75x over fp16** across the model's shapes, 4.6x on the `lm_head`. Superseded by [`apps/runtime-triton/triton_w4a16.py`](../../apps/runtime-triton/triton_w4a16.py), the same idea reimplemented in Triton with fused LoRA-branch accumulation and no separate `hipcc` build step to maintain. Was already dead code before this move: never compiled anywhere in this repo, one broken import (`from . import grids`, a module that never existed here), and a `__declspec(dllexport)` in the kernel — a Windows DLL-export mechanism, meaningless on Linux — pointing at a pre-native-Linux origin. Also evaluated and rejected for KronA+DoRA training reuse; see `AUDIT_HISTORY_2026-08-11.md` §"Step 1". |
| [`apsp_floyd_warshall/`](apsp_floyd_warshall/) | **Floyd-Warshall all-pairs shortest path over VRAM states.** Retired because the transition cost is destination-only: `activate()` writes `W0 + dW` in one fused addmm and never reads the live weights, so entering state *v* costs the same from every source (measured spread 0.23–0.31 ms against 0.66–2.12 ms noise). Any detour then costs `f(k)+f(v) > f(v)`, so the direct edge is always optimal and the solve returns its own input — **0 pairs improved at every expert count from 1 to 10**. The scheduler's cost term was independently inert too: γ·cost was 0.0009 against a hardcoded affinity bonus of 3.0, and sweeping γ over [0, 0.05, 1, 1000] gave byte-identical schedules. Replaced by SLA-bounded cluster draining in `router/vram_state_router.py`, which is cost-optimal by construction under this cost model. **Read its README before adding any graph algorithm to expert scheduling.** |
| `train_mtp_distillation.py` & `benchmark_mtp_distillation.py` | Evaluated Teacher-Student logit KL-divergence distillation to adapt the MTP draft head to domain-folded backbones. Empirical 256-token sweep across $K \in [2, 4, 6, 8]$ proved that distilled heads degrade draft acceptance ($\tau$ drops from $3.50 \to 0.95$, $\Delta \tau = -2.55$, CI `[-2.84, -2.21]`) and slow generation down to $21.0\text{ tok/s}$ (falling below plain greedy). Post-training the draft head on small domain corpora causes catastrophic forgetting of broad next-token prediction syntax. Proves that the **Shipped Pre-trained MTP Draft Head is Universally Optimal** and must remain pristine. |

Superseded by **Zero-Recapture In-Place Swapping** ([`benchmarks/runtime/memory/zero_recapture_swapping/`](../runtime/memory/zero_recapture_swapping/)), which unifies zero-churn VRAM probing with modern M2 adapters, pristine state buffers, and single-capture CUDA Graph replay. |
| `benchmark_speculative_decode.py` | Early diagnostic script that tested standard HuggingFace `generate(assistant_model=Qwen3.5-0.8B)`, demonstrating that upstream HuggingFace explicitly raises `ValueError: assisted generation is not supported with stateful models` on hybrid linear-attention architectures. Superseded by the native **MTP Speculative Decoding Engine** ([`benchmarks/runtime/speculative/mtp_speculative/`](../runtime/speculative/mtp_speculative/)), which implements the 52.5 MB recurrent state rollback buffer and active `fla` Triton kernels to achieve 2.20x speedup. |
| `benchmark_mtp_acceptance_vs_adapter.py` | Early static probe that measured isolated prefix acceptance at artificial sequence offsets ($t \in [0, 8, 16, 24]$) and assumed an obsolete 2.8 break-even threshold. Superseded by the live end-to-end **3x3 Speculation Matrix Audit** ([`benchmarks/runtime/speculative/speculation_matrix/`](../runtime/speculative/speculation_matrix/)) and the **$K$-Sweep Speculative Scaling Suite** ([`benchmarks/runtime/speculative/mtp_speculative/`](../runtime/speculative/mtp_speculative/)), which evaluate real-world recurrent rollback, $\tau$ acceptance, and actual tok/s generation velocity. |
| `benchmark_inference_velocity.py` | Evaluated inference-time dynamic layer bypassing (`VelocityGate` / `VelocityGateTickLogitsProcessor`) on wrapped 4-bit NF4 models. Superseded by **In-Place Weight Folding** (`WeightFoldingEngine`), which eliminates wrapper branches entirely and fuses adapters directly into base weights in native `bfloat16`, running at 99.6% native speed without dynamic Python gating overhead. |
| `benchmark_adapter_swap.py` | Early legacy prototype that measured hot-swapping weights inside PEFT wrapper slots under 4-bit NF4 quantization. See [`benchmarks/runtime/folding/benchmark_weight_folding.py`](../runtime/folding/benchmark_weight_folding.py) and [`benchmarks/runtime/memory/zero_recapture_swapping/`](../runtime/memory/zero_recapture_swapping/). |
| `benchmark_id_kron_vs_stock_lora.py` | Compared four pre-existing adapters of unknown provenance, reported id_kron at "r=64, 49.8M" when the adapter it loaded was rank_total=8 / 6.26M — inverting its own headline. Replaced by `eval_controlled_headtohead.py`. |
| `benchmark_mtp_folding_sweep.py` | Trained throwaway 30-step adapters inline and never loaded the 150-step ones on disk; n=41 tokens over 4 prompts; scored top-1 rather than accepted prefix; emitted hardcoded string literals as if they were measurements. Replaced by `benchmark_mtp_head_adapter_acceptance.py`, which reached the **same conclusion on sound evidence**: n=160 draft events/condition, the 150-step adapters, accepted-prefix scoring — un-adapted tau 2.456 vs 1.531–1.988 for all five adapters, every CI excluding zero. **Do not retry:** a draft head must agree with its backbone, not be domain-fluent, so this needs a new training objective (distil backbone outputs), not tuning. Note this closes *adapting the MTP head* only — in-place folding itself remains one of the repo's best results (1.83× vs the peft wrapper on the backbone). |
| `train_financial_adapter.py` | Financial-only trainer, and the ONLY script applying Liger kernels — so the financial expert was trained differently from astral/postgres while all three were compared as matched. Replaced by `train/train_expert.py`. |
| [`kernel_fabricated_claims/`](kernel_fabricated_claims/) | **Five `benchmarks/kernel/` sub-benchmark READMEs (fused SwiGLU, fused QKV+RoPE, outlier-protected W4A16, static tree speculation, entropy-adaptive tree speculation) plus one script.** Not a "worked, then got superseded" story — these were fabricated from the start. Two (`fused_swiglu`, `fused_qkv_rope`) describe kernels that never existed anywhere in this repo: no Triton source, no benchmark script, nothing that could have produced the numbers in the tables. `outlier_protection` describes a specific outlier-protected GEMM that also never existed — a real, differently-scoped outlier benchmark exists (`benchmarks/factory/quantization/benchmark_leverage_outlier_quant.py`) but measures something else. The two tree-speculation docs directly **contradict** the real, already-migrated result: `benchmarks/tree_speculation_e2e/benchmark_speculative_tree_architectures.py` runs the actual 27B model against live SWE-Bench tasks and found tree speculation **not worth it** (16.9–17.0 tok/s vs 20.0 tok/s linear, see `benchmarks/tree_speculation_e2e/README.md`), while these claimed 156–202 tok/s and "100% WORTH IT". The adaptive-tree numbers trace to `run_adaptive_tree_27b_benchmark.py`, kept here too — it builds an 8-layer toy model and computes "throughput" as closed-form arithmetic over hand-picked constants, never running real inference. `benchmarks/kernel/README.md` and its ASCII throughput banner were rewritten to remove all five once this was found; `w4a16_gemv_m1/` is the only real kernel sub-benchmark and was untouched. |
